Agentforce Vibes Walkthrough

🕓 8 minutes
⚠️ Stop — check you're in a sandbox

Before you make any changes, confirm the org you're logged into is your fullcopy sandbox, not production. Check the org name in the top-right user menu.

This matters especially for the next steps — only activate MCP servers and build in your sandbox, never in production.

Agentforce Vibes is a browser-based AI-powered IDE built directly into Salesforce. It always starts in a sandbox, so your data is already masked and no PII ever reaches the developer. There's nothing to install and nothing to configure.

Activate MCP Servers

MCP (Model Context Protocol) servers connect Agentforce Vibes to your org's capabilities. Before you launch Vibes, activate two servers in your sandbox.

1 Navigate to MCP Servers

In your sandbox, go to Setup → search for mcp ser in Quick Find → MCP Servers under Integrations > API Catalog. You'll see a list of available servers, all with status Inactive.

2 Activate salesforce-api-context

Click salesforce-api-context from the list, then click Activate. This server provides Agentforce Vibes with Salesforce API context so it can generate code that works with your org's specific configuration.

3 Activate metadata-experts

Go back to the MCP Servers list and click metadata-experts, then click Activate. This server allows Agentforce Vibes to discover and inspect your org's metadata — objects, fields, relationships, and configurations.

Open Agentforce Vibes

4 Enable Einstein

In your sandbox, click the gear icon in the top right to open the Setup Menu and select Setup. In the Quick Find box, enter and select Einstein Setup. Toggle on Turn on Einstein.

5 Launch from the Setup Menu

Click the gear icon in the top right to open the Setup Menu. You'll see Agentforce Vibes listed with an external link icon. Click it to launch.

6 Wait for the environment to load

Agentforce Vibes will set up your virtual environment. This may take a few minutes on first launch — leave the page open and it will refresh when it's ready.

The IDE

7 Welcome page and file explorer

Once loaded, you'll see the Agentforce Vibes IDE welcome page. The left panel shows the Explorer with your dx-project — this is the Salesforce DX project structure you will work with. Notice that it is automatically connected to the sandbox. If you don't see the Explorer panel, click the file icon in the top of the left activity bar to open it.

8 The "Let's Vibe" sidebar

Click the Agentforce Vibes icon in the left activity bar to open the Let's Vibe sidebar. You may be prompted to enable Agentforce Vibes — click Enable to proceed. This is your starting point for working with the AI agent.

At the bottom of the sidebar, notice the Plan and Act mode toggles and the prompt input where you'll type your tasks.

MCP Servers

9 Connected MCP servers

Click the Toolkit tab and then MCP Servers to see all three connected servers:

  • Salesforce DX — access to org metadata, deployment, and source tracking
  • Salesforce API Context — understands your org's API structure and data model
  • Salesforce Metadata Experts — discovers and resolves metadata types and dependencies

Each server shows a green dot indicating it's active. Through these MCP servers, the agent knows your custom objects and your business logic. It doesn't guess your schema — it reads it.

Skills

10 What the agent can do

In the Toolkit tab, select Skills to see the list of available skills. Skills define what the agent can do — the actions it can take and the systems it can interact with.

Salesforce ships out-of-the-box skills built on years of platform best practices, including:

  • generating-lightning-app — build complete Lightning Experience applications
  • generating-apex — create Apex classes and triggers
  • generating-custom-object — scaffold custom objects and fields
  • generating-custom-tab — create custom tabs for your app
  • generating-permission-set — define permissions and access

You can click any skill to view its SKILL.md file, which describes when and how the agent uses that skill.

Rules

11 How the agent behaves

In the Toolkit tab, select Rules to see the governance guardrails. Rules define how the agent behaves — the boundaries around security, data access, and best practices.

Salesforce provides out-of-the-box rules like a4v-expert-global-rule.md that ensure every interaction operates inside a defined, governed system. These rules enforce standards around code quality, security patterns, and Salesforce platform conventions.

Metadata Explorer

12 Retrieve org metadata

Select the Chat tab, then type the following prompt in the input at the bottom:

Retrieve all custom objects associated with the app Connected_Executive_Education from my org into the project folder, make sure to create a manifest before retrieving.

Agentforce Vibes will create a manifest file and retrieve the metadata from your sandbox into the project folder.

Approve requests to proceed

Agentforce Vibes will ask for permission before executing actions. You can approve each request to let it proceed. If prompted to choose an org, select the default option.

13 Explore objects and fields

In the Explorer, expand force-app > main > default > objects to see the three custom objects: Course__c, Enrollment__c, and Student__c. Expand any object to browse its fields.

14 Visualize the schema

Click on any field file to open it in the editor. Then click the Visualize button in the top right to see a visual representation of your custom objects and their relationships.

You can see how Enrollment__c connects to both Student__c and Course__c through lookup fields, along with every field and its data type.

Governed by design

Every interaction in Agentforce Vibes operates inside a governed system. Skills define what the agent can do. Rules define how it behaves. MCP servers connect it to your org metadata. And sandbox boundaries ensure you're always building safely — security and governance are built into the platform, not bolted on after.
