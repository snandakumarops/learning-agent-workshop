Working with Policies in Data Mask & Seed

🕓 15 minutes

Before real work happens in a sandbox, sensitive production data needs to be masked. In this lab you'll open an existing Data Mask & Seed policy, add a custom object to it, configure field-level masking using libraries, save, and run the policy against your sandbox data.

Prerequisite

You must be working in a sandbox org with Data Mask & Seed installed and the Student custom object available. Confirm you are in your sandbox before proceeding.

Open the policy

1 Open Data Mask & Seed

Click the App Launcher (grid icon, top-left corner). In the Quick Find search box, type Data Mask & Seed and select it from the Apps list.

You'll land on the Home tab showing features: Bypassing Automations, Proactive PII Detection, and Maintain Field Value Distribution.

2 View the Policies list

Click the Policies tab in the top navigation bar. The All Policies list view appears showing all configured masking policies. Locate Mask Customer Information and click its name to open it.

You should see the policy description, Locale, Run on Refresh setting, Schedule, and the Objects already configured (Contact and Lead).

3 Review the existing policy

Take a moment to review the current configuration:

  • Locale: US English
  • Run on Refresh: No
  • Schedule: No Schedule
  • Objects: Contact & Lead

The first object is selected by default. Fields show Categories, Mask Unique, and Mask With settings. Fields set to Skip won't be masked.

Add and configure the Student object

4 Enter edit mode

Click the Edit button (upper-right corner). The button changes to Save, the field-level dropdowns become active, the Add Filters button becomes available per object, and + Add appears in the Objects panel.

5 Add the Student custom object

In the Objects panel on the left, click + Add. In the Add an Object dialog:

  1. In Quick Find, change Object Type to Custom and type student
  2. The Student object appears (Type: Custom)
  3. Click the + icon next to Student
  4. Click Add to confirm

6 Configure field masking for Student

The Student object has three fields to mask:

  • First Name (First_Name__c) — Text(80)
  • Last Name (Last_Name__c) — Text(80)
  • Email (Email__c) — Email (External ID)

Mask First Name: find the First Name field and, in the Mask With dropdown, select the First Name library.

Mask Last Name: find the Last Name field and, in the Mask With dropdown, select the Last Name library.

Mask Email: the Email field is already configured to Mask With the Email library. When you add a new object to a policy, Data Mask & Seed automatically scans its fields and recommends masking for fields it identifies as PII.

Using libraries

Libraries provide realistic replacement values that maintain data format integrity. For text name fields, a First Name or Last Name library generates plausible replacement names; the Email library generates valid-format email addresses. You can view and manage them under the Custom Libraries tab.

Save and run

7 Save the policy

Click Save (upper-right corner). The policy exits edit mode. Confirm that Student now appears alongside Contact and Lead in the Objects panel.

⚠️ Data Mask & Seed can only be run in a Sandbox

A policy can be configured in production, but it can only be run in a Sandbox. Running the policy is irreversible for that sandbox refresh cycle — the masked values replace the original data in your sandbox. Make sure you are in your sandbox before continuing.

8 Run the policy

Click Run Now (upper-right corner) and confirm in the dialog. The masking job will:

  • Bypass sandbox automations (workflow rules, triggers, validation rules)
  • Apply masking to all configured fields on Contact, Lead, and Student
  • Maintain field value distribution

Verify

9 Confirm the masking

  • Check the Last Run Date on the policy
  • Navigate to Student records and verify First Name, Last Name, and Email are masked
  • Review any error messages if records were skipped

Summary

In this lab you:

  1. Navigated to Data Mask & Seed via the App Launcher
  2. Located and opened the Mask Customer Information policy
  3. Entered edit mode and added the Student custom object
  4. Configured masking on First Name, Last Name, and Email using library-based masking
  5. Saved the updated policy
  6. Ran the policy to apply masking to sandbox data
Why this matters

Masking PII in a sandbox is the guardrail that lets teams build and test safely against production-like data — without exposing real customer information.
